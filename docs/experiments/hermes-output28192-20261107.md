## Change and scope

The user requested 28,192 output tokens. Hermes one-shot omits both output-limit
fields; the frontend previously used `min(1024, max_output)`, even when the server
advertised a larger allowance. `validate_request` now uses the configured
`max_output` when both fields are absent. Explicit smaller requests are honored;
`max_completion_tokens` retains precedence over `max_tokens`, and neither can
exceed the configured cap. This applies consistently to both serving backends
and any client that omits its limit.

Measured source: `4feadcc8216c7953e6a4e2c2643457be0029bfc6`. Both native profiles use **262,144 context,
28,192 output cap/default, 233,952 conservative input reservation, Q8 K/V cache**,
one slot, non-thinking mode and the same engine-verified Qwen instruct sampler.
The official base, released MLP factors, native LoRA and runtime are unchanged.
The predeclared protocol is [retained separately](hermes-output-28192-protocol-20261107.md).

No further training or historical HE9 generation is performed. The old nine-task
scores retain their original 8,192-token serving identity. They cannot be
substituted into the new profile's qualification. No default provider or adapter
promotion is changed.
